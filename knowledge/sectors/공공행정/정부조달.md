# 정부조달

## 한 줄
공공기관이 물품·용역·공사·외자를 사는 전 과정 — 발주계획부터 계약·쇼핑몰 납품요구까지 — 을 조달청 나라장터가 단계별 API로 공개한다.

## 행정 프로세스와 근거법
발주계획 → (중앙조달이면) 조달요청 → 사전규격 공개 → 입찰공고 → 개찰·낙찰 → 계약 / 단가계약 상품 → 쇼핑몰 납품요구.
근거: 국가를 당사자로 하는 계약에 관한 법률(국가계약법), 지방계약법, 조달사업에 관한 법률, 전자조달의 이용 및 촉진에 관한 법률.

## 기관
조달청 하나 (나라장터·누리장터·나라장터쇼핑몰). 2025-01-06 차세대 나라장터 개통.

## 개별 코드 (조인 키)
- 단계 번호: `R`+연도2+단계코드2+순번8 — DD 발주계획, DC 조달요청, BD 사전규격, BK 입찰공고, TA 계약, TB 납품요구
- 전역 키: 사업자등록번호(`key:bizno`), 행정표준기관코드(`key:instt_cd`), 조달청 물품분류번호(`key:g2b_prdct_clsfc_no`)
- 자세한 별칭·관계: [families/pps-procurement](../../families/pps-procurement/family.md)

## 대중 수요
B2G 기업의 입찰 기회 탐색·알림(입찰공고 API가 활용 최상위), 경쟁사 낙찰 분석, 기관 구매 행태, 업체 공공 매출 실적.

## 데이터 구성 (2026-07-31 스냅샷)
- 조달청 데이터 161건 = REST API 18 + 파일 143(대부분 기관 사이트 링크). 원래 BRM은 정부조달 58·일반행정 141 등으로 흩어져 있었음 → `pps-to-procurement`로 모음
- API 18종의 역할: 단계 7 · 허브 1(계약과정통합공개) · 마스터 5 · 집계 1 · 파생 1 · 민간 거울 3

## 앞 (심층 대상)
패밀리 전체가 하나의 체인. 대표: 입찰공고(15129394) · 낙찰(15129397) · 계약(15129427) · 사전규격(15129437) · 발주계획(15129462) · 쇼핑몰(15129471) · 사용자정보(15129466) · 물품목록(15129417), 연결은 계약과정통합(15129459).

## 뒤
공공조달통계(15129412, 집계), 업종·근거법규(15129467), 계약과정통합(번호 조회형 — 체인의 연결자이지 전수 원천이 아님).

## 제외·이관
- 제외: 조달청 외 기관 41건(대전광역시 계약현황, 발전사·공사 입찰/계약 파일 등) — 개별 기관 파일이라 나라장터 원천을 대체하지 못함 (`gov-procurement-non-pps`)
- 조달청 파일 143건은 API로 대체되므로 도시에 대상 아님

## 주의
업무구분별 오퍼레이션 분리, `inqryDiv` 의미가 오퍼레이션마다 다름, 조회기간 제한(1일~36개월), 중첩 문자열 목록, 구·차세대 번호 체계 혼재 — 패밀리 문서 §7.
