# 법제

## 한 줄
국회(의안·의정 활동)와 법제처(법령·자치법규·판례·해석례)의 외부 API가 거의 전부인 부문. 가치의 기준은 **"LLM이 이미 아는가"** — 큰 법령·규칙 본문은 이미 공개·학습돼 부가가치가 낮고, **빨리 올라오는 세부 원장(어제 발의된 의안, 지난주 선고된 판례, 오늘 표결)**이 이 시스템이 줄 수 있는 가치다.

## 코드 수렴
의안번호·의원코드·판례번호 셋이 **법령ID로 수렴**한다 (의안 → 공포번호 → 법령ID, 판례 → 참조조문 → 법령ID). 법령 원장(`statute`)은 정부자원관리의 행정표준코드(`reference-codes`)에 이은 **두 번째 시스템 공통 마스터** — Phase 3 첫 도시에 작업에 함께 들어간다.

## 대중 수요
1. 국민 → 판례·해석례 ("이거 불법인가", "비슷한 판례"). LLM 시대에 폭증, 법률 상담·챗봇·RAG 원천
2. 기업·컴플라이언스 → 개정 추적 (시행일 예정 법령, 신구법 비교, 위임 하위법령)
3. 언론·시민 → 의안·표결·의원. 선거(국정운영) 후보자ID와 의원코드가 매핑되면 "공약 → 발의 → 표결"
4. 지자체·행정 실무 → 자치법규·행정규칙

## 주의 (이 부문 특유)
1. **키가 data.go.kr 것이 아니다.** 법제처는 `open.law.go.kr`의 OC 값, 국회는 `open.assembly.go.kr` 자체 인증키 → `knowledge/key_issuers.yaml`, 도시에 `access.key_issuer`. 계정은 `.env`에 사이트별로 있음(값은 문서에 남기지 않는다)
2. **공개 지연 실측이 핵심 수치.** 의안 발의일 ↔ API 등장일, 판례 선고일 ↔ 등록일의 차이 = Phase 2 단계 j `event_to_publish_lag`. `bill`·`case-law` 도시에와 전략 응답("사건 후 N일 내 반영")에 쓴다. 수정일 기준 freshness로는 못 잡는 값
3. 국가중점 지정이 시리즈 단위로 몰려 있어 이 부문에서 designation은 사실상 무의미 (가중치 0.05로 이미 보정)
4. 법령해석례는 부처별 목록·본문(목록 기준 39종)으로, 위원회 결정문·재결례는 12종으로 쪼개져 있다 → 도시에는 "법령해석례" 하나로 묶고 부처는 파라미터로
