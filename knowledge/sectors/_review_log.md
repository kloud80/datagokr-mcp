## 공공행정 - 정부조달 (2026-09-28, 구름)

- **결정**: 조달청 데이터만 남긴다. 조달청 외 기관 41건은 제외.
- **이유**: 나라장터(조달청)가 공공조달의 원천이다. 다른 기관 데이터는 자기 기관의 계약현황·입찰결과 파일이라 나라장터 API로 대체되거나 범위가 좁다.
- **후속**: 조달청 API들이 어떻게 이어지는지 별도 정리 → [데이터 패밀리 pps-procurement](../families/pps-procurement/family.md). 이 방식을 다른 기관 API 묶음에도 적용한다(표준: [families/README.md](../families/README.md)).
- **참고**: 조달청 REST API 18종 중 4종은 다른 영역에 분류돼 있다 — 입찰공고·개방표준(일반행정), 통계(국가통계), 가격(정부자원관리). 부문 확정 시 조달로 모은다.

## 공정거래 (2026-09-28, 구름)

- **결정**: 공정위의 등록·지정·공시 4개 체인만 대상 — **기업집단 · 가맹사업 · 특수판매(통신판매·다단계·방문·후원방문·전화권유) · 상조(선불식할부)**. 나머지는 제외 (`exclusions.yaml` `ftc-non-core`).
- **부문 병합**: 공정위 데이터 266건이 공정거래(62)·산업·중소기업일반(121)·산업금융(67)·일반행정(13)·법제(3)로 흩어져 있던 것을 `공공행정 - 공정거래` 하나로 (`sector_map.yaml` `ftc-to-fairtrade`). 같은 방식으로 조달청 161건도 `공공행정 - 정부조달`로 모음 (`pps-to-procurement`).
- **이유**: 대중 수요는 셋 다 "이 사업자 믿어도 되나" — 창업 예정자(가맹 정보공개서), 소비자(통신판매·상조 등록 확인), 투자·언론(기업집단 지분·내부거래). 개방 데이터가 있는 곳도 등록·지정·공시 영역뿐이고, 네 체인 모두 **사업자등록번호·법인등록번호**로 묶인다. 하도급 실태조사·1372 상담통계·기업결합은 집계, 결정문·리콜은 사건·문서 단위라 연계 불가.
- **제외된 타 기관 데이터**: 지자체 물가·착한가격업소(행안부 물가정책)·통신판매업 파일, 부산·인천 정보공개서 파일(공정위 가맹사업정보제공시스템이 전국 원장), 공기업 계량·경영 자료 등.
- **판정 기준**: 앞(핵심) = 체인 대표 API(도시에 대상) · 앞 = 건별 + 연계 키 · 뒤 = 집계·통계·순위 또는 연계 키 없음 · 제외 = 규칙으로 대상 밖.
- **체인별 개별 코드**: 기업집단코드 · 가맹본부관리번호/브랜드관리번호(+정보공개서 등록번호) · 인허가관리번호(통신판매 등) · 선불식할부 등록번호 → 모두 사업자등록번호로 묶임.

## 국정운영 (2026-09-28, 구름)

- **결정**: 정책영역 하나에 선거·지방의회·관보·대통령기록·정책자료가 섞여 있어 세부 부문 8개로 재분류 (`subsectors.yaml`). 심층(앞)은 **선거** 하나.
- **참고 설계와의 차이**: 참고안(선거·정치자금·규제·국정과제·대통령기록·감사윤리)을 실제 데이터에 맞춰 조정 — 정치자금·규제·감사는 포털에 데이터가 없어 공백(gap)으로 기록, 실제로 많은 지방의회(33)·관보(11)·연구자료(14)를 세부 부문으로 추가.
- **이관**: 선관위 52건을 국정운영/선거로(국가통계 22·일반행정 1 포함, `nec-to-election`). 오분류 반환: 환경영향평가 5 → 환경기상, 법제처 법령 API → 법제, 개인정보위 4 → 국민권익·인권.
- **선거 주기 예외**: `cycle: event` — 마지막 선거(2026-06-03) 이후 수정 1.0, 아니면 0.7.
- 설명서: [공공행정/국정운영.md](공공행정/국정운영.md), 전체 목록: `reports/phase1_fields/01_공공행정.md` §3
