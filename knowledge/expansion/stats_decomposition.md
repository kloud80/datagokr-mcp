# 통계·거시 데이터 분해 연구안 (초안 · 2026-10-14)

> 상태: 제안 — 구름 검토 전. 키 없이 되는 부분(KSIC 허브·업종 매핑 1판)은 2026-10-15에 초안을 만들었다 → §7.

## 1. 문제 — 통계표는 '한 덩어리'가 아니다

지금 지식 체계는 데이터를 **표 단위**로 본다 (메타·필드 구조·표본 행). 통계표에 이 방식을 쓰면
"OO조사 결과 — 거시 통계 · 전국/시도 · 연" 한 줄로 끝난다. 그런데 통계표의 **행 하나하나는 서로 다른 대상**이다.

| 통계표 | 행 하나가 실제로 뜻하는 것 |
|---|---|
| 서비스업조사 (시군구 × 산업 × 항목) | "성동구 · 커피전문점(KSIC 56221) · 매출액" — 특정 지역 특정 업종의 지표 |
| ECOS 산업별 대출금 (산업 × 기간) | "음식점 및 주점업 대출 잔액" — 한 업종의 금융 지표 |
| 소비자물가 (품목 × 지역 × 월) | "서울 · 쌀 · 지수" — 한 품목의 가격 지표 |
| 열린재정 세출 (소관 × 분야 × 프로그램) | "보건복지부 · 사회복지 · 기초연금 지급" — 한 정책 사업의 돈 |

그래서 통계는 **표가 아니라 '축(분류)과 축 값' 단위로 분해**해야 미시 데이터(인허가·상가·실거래·시설)와 이을 수 있다.
행이 어떤 업종·지역·품목·기관을 대표하는지는 메타가 아니라 **데이터 값 자체**에 있으므로 전량을 내려받아야 한다.

## 2. 대상 원천

| 원천 | 내용 | 접근 | 축의 예 |
|---|---|---|---|
| KOSIS (통계청·승인통계 기관) | 통계표 수만 개 (정확한 수는 목록 수집으로 확인) | `KOSIS_API_KEY` — 목록·메타·자료 API, 대용량은 파일 | 행정구역 · 산업(KSIC) · 성·연령 · 규모 · 품목 |
| 한국은행 ECOS | 경제통계 표 수백 개 · 항목 수만 개 | `ECOS_API_KEY` — 표 목록·항목 목록·자료 API | 산업 · 지역 · 상품 · 기관 부문 |
| 열린재정 (나라 살림) | 중앙정부 세입·세출 예산·결산 | `OPENFISCAL_API_KEY` | 소관(부처) · 회계 · 분야·부문 · 프로그램 · 단위사업 |
| 지방재정365 (지자체 살림) | 지자체 세입·세출 | `LOFIN365` 키(보유 확인 필요) | 지자체 · 분야·부문 · 세부사업 |
| 한국부동산원 R-ONE | 가격지수·거래량·임대 통계 | `REB_API_KEY` | 지역 · 주택 유형 · 규모 |
| SGIS | 집계구·격자 통계 | `SGIS_CONSUMER_KEY/SECRET` | 집계구 · 격자 (공간 단위가 가장 잘다) |
| 포털 안의 통계 파일 | 지금 검증된 통계류 약 1.1만 건 | 보유 | 같은 방식으로 다시 분해 |

통계청 가계동향조사(가구의 가계부)도 KOSIS 안에 있다 — 소득분위 · 지출 품목(COICOP) 축으로 분해된다.

## 3. 분해 모델

```
통계표 (table)            KOSIS orgId+tblId · ECOS STAT_CODE · 열린재정 데이터셋
 └ 축 (axis)              분류 하나 — 예: '산업', '행정구역', '항목', '기간'
    └ 축 값 (member)      '커피 전문점', '성동구' … — 원천 코드와 이름
 └ 시리즈 (series)        측정 항목 × 축 값 조합 — 단위 · 주기 · 시작~끝
    └ 관측 (observation)  기간 · 값 (long 형식 parquet)
```

- **축 유형 판정**: 축 값 집합을 보고 유형을 정한다 — `region`(시도·시군구·읍면동) · `industry`(KSIC) · `product`(품목·HS·COICOP) ·
  `demographic`(성·연령·가구) · `org`(기관·부처) · `fiscal`(분야·부문·프로그램) · `size`(규모 구간) · `measure`(측정 항목) · `other`.
  규칙(값의 90%가 행정구역 이름·코드와 맞으면 region 등)을 먼저 쓰고, 남는 것만 LLM이 판정한다.
- **축 값 → 허브 코드 매핑**: 지금의 매핑(`knowledge/mappings`)과 같은 방식으로 **실측 일치율**을 남긴다.
  - region → 기존 허브 법정동 코드표(15123287) — 시군구 5자리 · 시도 2자리, 행정구역 변경 연계표
  - industry → **새 허브: 한국표준산업분류(KSIC)** — 9·10·11차 연계표 포함. 지금 지식 체계에 없다 (상가업소 ksicCd 코드표 하나뿐)
  - product → HS 코드표(보유) · COICOP(새로) · 품목 이름 사전
  - org → 기관코드 · fiscal → 재정 분류 코드
- **색인 단위**: 표가 아니라 **축 값**도 검색 대상으로 한다. "커피전문점 매출"을 물으면 KSIC 56221을 가진 통계표 축 값이 걸린다.
  조합 전체(시리즈 수백만 개)를 카드로 만들지 않고, 축 값 이름 + 표 정보만 색인한다.

## 4. 연동 — 새 Edge 종류

| Edge | 뜻 | 예 |
|---|---|---|
| `benchmark` (미시 → 거시) | 미시 데이터의 업종·지역을 같은 축 값을 가진 통계 시리즈에 붙인다 | 성수동 휴게음식점 인허가 → (업태명 → KSIC 56221 매핑) → 서비스업조사 성동구 커피전문점 사업체 수·매출 |
| `shares_axis` (거시 ↔ 거시) | 같은 축(KSIC·시군구·기간)을 공유하는 통계끼리 직접 조인 | ECOS 업종별 대출 × KOSIS 업종별 사업체 수 → 업체당 대출 |
| `fiscal_to_place` | 재정 사업을 지역·시설과 잇는다 | 지자체 세출(복지 분야) × 시군구 복지시설 수 |

- 미시 쪽에는 **업종 → KSIC 매핑표**가 필요하다: 인허가 업태명(LOCALDATA 업종 200여 개) · 상가 업종 분류 · 사업자 업종 코드 → KSIC.
  이것이 이 연구의 핵심 산출물이다. 소상공인 상가정보에는 이미 ksicCd가 있어 출발점이 된다.
- 시간 단위가 다르면 지금의 단위 불일치 규칙(`unit_gaps`)을 그대로 쓴다 (월 요청 × 연 통계 → 공백으로 밝힘).
- 플래너에는 역할 `benchmark`(맥락 지표)를 추가한다 — 핵심 데이터가 아니라 '비교 기준'으로 답에 붙인다.

## 5. 단계

| 단계 | 할 일 | 규모·조건 |
|---|---|---|
| 0. 키 | KOSIS · ECOS · 열린재정 · R-ONE · SGIS 가입 | 구름 (가입 목록 참조) |
| 1. 시범 | ECOS 전체 + KOSIS 핵심 통계 10종(전국사업체조사 · 서비스업조사 · 경제총조사 · 광업제조업조사 · 주민등록인구 · 지역별고용조사 · 가계동향 · 소비자물가 · 농림어업총조사 · 사망원인) + 열린재정 세출 | 메타 전수 + 자료 전량. KSIC 허브와 업종 매핑표 1판 |
| 2. 검증 | 연동 시연 3개 (위 Edge 표의 예) + 포털 비교 1,000문항 중 통계형 질문 재평가 | 진 문항(전국 통계 누락) 회복 여부를 잰다 |
| 3. 확대 | KOSIS 목록 전수 → 축 유형 판정 → region·industry 축이 있는 표부터 자료 전량 | 저장 공간·호출 한도에 맞춰 우선순위 |
| 4. 상시 | 통계 공표 주기에 맞춘 갱신 · 분류 개정(KSIC 11차 등) 연계 | |

## 6. 위험과 미정

- **분량**: KOSIS 전량은 수십 GB 이상일 수 있다 — 시범에서 표당 셀 수를 재고 3단계 범위를 정한다.
- **호출 한도**: KOSIS 자료 API는 호출당 셀 수 제한이 있어 축을 나눠 부른다. 큰 표는 파일 다운로드를 쓴다.
- **분류 버전**: 같은 '산업' 축도 표마다 KSIC 차수가 다르다 — 연계표 없이는 시계열이 끊긴다.
- **억제값**: 통계는 비밀보호로 값이 '-'·'X'로 가려진 칸이 많다 — 결측과 0을 구분해 남긴다.
- **업종 매핑의 모호함**: 인허가 업태 하나가 KSIC 여러 개에 걸친다 — 일치율과 1:N을 그대로 기록하고 추정이라고 표시한다.

KSIC 원천이 포털에 새로 올라와(`_plan.yaml`에서 portal_absent였던 것) 통계분류포털 없이 complete로 확보했다.

단계별로 붙은 이름 수: KSIC 11차 이름 그대로 11,622 · 이름에 적힌 코드 2,155 · 사전 611 · 쉼표 묶음 360 · 10차 이름 240 · 어업 규칙 92 · 상권업종 이름 38.

발견한 것
- 공장등록·지자체 공장 현황 계열은 업종 이름이 이미 **KSIC 항목명 그대로**다 ('… 제조업 외 1 종') — 일치의 대부분.
- 상가정보의 `표준산업분류코드`는 **10차**다 (코드 일치 99.7%, 11차는 91.8%) — 11차 통계와 이으려면 연계표를 거쳐야 한다.
- 이름에 코드를 적은 값 중에는 **9차 코드**가 섞여 있다 — `판유리 가공품제조업(23122)`의 23122는 9차로는 판유리 가공품, 10·11차로는 디스플레이용 유리. 적힌 이름과 가장 닮은 차수로 읽게 했다.
- 상권업종 분류 자체에도 오류가 있다 — '일식 회/초밥'에 '한식 일반 음식점업'이 붙은 행 등. 그래서 소분류마다 최빈값만 쓰고 비중을 confidence로 남겼다.
- 인허가 업종은 법령 단위라 KSIC보다 넓다 — `일반음식점`(561 전체, 0.7) · `휴게음식점`(5622+5619). 통계와 이을 때는 상위 단계(R-23)로 올려야 한다.

검토가 필요한 것 (구름)
1. 사전의 confidence가 낮은 판정 — 산후조리원(96993, 0.6) · 키즈카페(91299, 0.6) · 무도학원업(85613, 0.6) · 식용얼음판매업(46332, 0.5) · 게임물배급업(58219, 0.5) · 용기.포장지제조업(C, 0.5).
2. skip 목록(업종이 아닌 값) — 집단급식소 '설치 장소'(학교·산업체·군부대…)와 가스·수도 '용도'(가정용·일반용…)를 업종에서 뺀 것이 맞는지.
3. 다음 단계: `ksic` 키(knowledge/keys)를 선언해 Edge 자동 생성(pds/edges/auto.py)에 올리기 — 지금은 매핑 파일만 있고 Edge는 없다. 통계 쪽 KSIC 축은 KOSIS·ECOS 키가 생긴 뒤 붙인다.

다시 만들기: `python -m pds.codes.build` (ksic·ksic10 포함) → `python -m pds.mapping.build_industry` (약 10분, 검증 데이터 yaml 전수 읽음).
