# 포털 AI 검색과의 비교 (2026-10-07)

공공데이터포털 [AI 검색](https://www.data.go.kr/tcs/dss/aiAssistant.do)과 우리 답을 같은 질문 45개로 비교했다.
질문은 정답표(`evals/plan_recall.yaml`) 32개와, 두 주제가 섞였거나 제외 규칙에 걸릴 만한 경계 영역 13개다(`questions.yaml`).

| 파일 | 내용 |
|---|---|
| `portal/q*.json` | 포털 답 — 추천 카드 5개(분석 정보·추천 이유) + 오른쪽 추천데이터 30개(정확도순) |
| `ours/q*.json` | 우리 답 — 전략(LLM 없이) datasets·단서 + 채팅 답(도구 호출 포함) · `run_ours.py` |
| `report.json` | 질문별 대조와 포털 추천 중 우리가 못 낸 것의 이유 · `compare.py` |
| `judge/q*.json` | Opus 판정 — 데이터별 관련성 0~2, 두 답 비교(출처 숨김·A/B 무작위) · `judge.py` |
| `missed_core.json` | 포털 추천 중 '핵심(2점)'인데 우리가 못 낸 40건 |
| `proto_leads.py` · `proto_rerank.py` | 단서 검색 개선 시제품과 측정 |

**주의** — 판정은 LLM 한 번이며, 구조화된 긴 답을 선호하는 편향이 있을 수 있다. 포털 AI는 같은 질문에도 답이 매번 달랐다(q01을 세 번 물어 세 번 다른 추천).
포털 답은 1회 수집본이다.

## 결과

**답 전체**: 우리 44 · 포털 1 (정답표 32문항 전승, 경계 영역 13문항 중 12승).

| 기준 (1~5) | 포털 | 우리 |
|---|---|---|
| 관련성 | 3.51 | 4.58 |
| 측면 포괄 | 2.80 | 3.98 |
| 바로 실행 (잇는 법·받는 법) | 1.89 | 4.42 |
| 정직성 (과장 없음·한계 명시) | 2.36 | 4.58 |

**데이터 단위 정밀도는 포털이 낫다**:

| | 핵심(2점) | 무관(0점) |
|---|---|---|
| 포털 추천 상위 5 | **55%** | 10% |
| 우리 전략 상위 5 | 40% | 19% |
| 우리 전략 전체(8) | 36% | 20% |
| 우리 채팅 답이 고른 데이터 | 51% | 2% |

우리가 이기는 이유는 '데이터를 어떻게 잇고, 어디서 키를 받고, 무엇이 없는지'다. 데이터 고르기 자체는 포털이 앞선다.
포털에 없고 우리만 낸 핵심 데이터는 90건, 포털엔 있는데 우리가 못 낸 핵심 데이터는 40건이다.

### 구조적 원인

1. **제외가 '나중에 검증'이 아니라 '추천 불가'로 작동한다.** 포털 목록 96,110건 중 50,281건(52%)이 제외 규칙에 걸려 있다. 원래 뜻은 검증 우선순위였는데, 제외된 데이터는 전략에 들어갈 수 없고 단서 검색에서도 밀린다.
2. **검증 대상 선정이 '전국 원장·표준데이터'를 놓친다.** 놓친 핵심의 절반(18/40)이 질문의 정답 격인 전국 단위 원장이다.
3. **플래너 보정이 1위를 밀어낸다.** 맥락 멤버 순서(×1.4~1.0)·등급 감점(보조 ×0.6)·메타 적합도가 글자 검색 1위 검증 데이터를 전략 밖으로 밀어낸 사례가 있다.
4. **단서 검색은 '찾기'가 아니라 '줄 세우기'가 문제다.** 정답(핵심 2점)의 87%가 후보 풀(문장 + 역할별 검색어, 각 상위 300)에 이미 있는데, 상위 10에는 31%만 든다.

   | 단서 검색 방식 | 상위 10 안 정답 |
   |---|---|
   | 지금 (문장 전체 BM25) | 31% |
   | + 응답 필드·설명 400자 | 29% |
   | + 역할별 검색어(규칙/LLM) 순위 합치기 | 20% / 28% |
   | 후보 풀 → Haiku 재순위 | 38% |
   | **후보 풀(넓게) → Sonnet 재순위** | **54%** (풀 상한 75%) |

5. **채팅이 빈칸을 다시 찾지 않는다.** 45문항 모두 `plan_strategy` 한 번(+제외 표시)으로 끝났고 `search_datasets`·`get_dataset`은 0회다. 작황 질문에서 "타깃 데이터가 없다"고 쓰고도 '작황'으로 다시 찾지 않았다.
6. **포털 답의 강점** — 데이터마다 무엇이 들어 있는지(필드·기간·형식·갱신)를 한 단락으로 보여 주고, 후속 질문 3개를 제안한다. 우리 답은 내부 id(`e-37245`, `R-13`)가 새어 나오고 핵심 대상 대신 우회 경로를 앞세운 경우가 있었다(반려동물 질문 — 유일한 패배).

## 개선안 (효과 큰 순)

| # | 무엇 | 근거 | 비용 |
|---|---|---|---|
| 1 | **단서 재순위** — 문장 + 역할별 검색어로 넓은 후보 풀을 만들고 Sonnet이 질문 기준으로 다시 줄 세움 | 상위 10 정답 31% → 54% | 질문당 LLM 1회 (~3초) |
| 2 | **채팅 빈칸 재탐색** — 전략의 공백·역할마다 `search_datasets(catalog)`를 부르게 지침과 도구 흐름을 바꿈 | 45/45 단발 호출 | 지침 수정 |
| 3 | **제외의 뜻 분리** — 제외는 검증 순서로만 쓰고, 질문에 핵심이면 단서로 올림. 단서가 핵심이면 그 자리에서 실측 프로브를 돌려 검증으로 승격(온디맨드 검증 큐) | 핵심 누락 9건 | 프로브 재사용 |
| 4 | **선정 보완** — 표준데이터·'전국' 원장을 선정 점수에서 올리고, 이번 누락 40건을 바로 검증 | 핵심 누락 18건 | 검증 1회 |
| 5 | **플래너 보정 완화** — 글자·의미 검색 1위 검증 데이터는 보정으로 탈락하지 않게, '보조' 감점은 전국 원장에 적용 안 함 | 핵심 누락 9건 | 소규모 |
| 6 | **포털 목록 의미 검색** — 9.6만 건 임베딩(RTX 3060 Ti로 GPU 실행 시 수십 분, CPU는 10시간+)으로 후보 풀 상한(75~87%)을 올림 | 재순위 상한이 풀 포함률 | GPU 실행 환경 |
| 7 | **답 표현** — 데이터별 '무엇이 들어 있나'(필드·기간·갱신·형식) 한 단락, 후속 질문 제안, 내부 id 숨김 | 포털 강점·유일한 패배 사유 | 지침·렌더 |
| 8 | **상시 비교** — 이 묶음을 정기적으로 다시 돌려 승률·정밀도 추적 | 포털 답이 매번 달라 여러 번 평균 필요 | 수집 1시간 |

## 멀티헤드 전략 적용 후 (2026-10-07)

개선안 1·2·3·5·7을 한 구조로 묶었다 — 질문을 주제(헤드)로 나눠 주제마다 따로 찾고(검증·선정·포털 목록, 목록은 응답 필드까지), 주제마다 Sonnet이 다시 줄 세우고,
주제 사이 연결(선언된 조인 > 같은 키 > 같은 단위 집계)로 대표를 다시 고른다. 제외 규칙에 걸린 목록 데이터도 후보에 든다. 코드 `pds/strategy/multihead.py`.

수집 `run_ours.py --out ours_heads --chat-only` → 판정 `judge_heads.py` (같은 Opus 지침, 새로 나온 데이터만 추가 판정) → `heads_report.json`.
v1·v2는 중간 버전(`heads_report_v1/v2.json`): v2에서 핵심 조인 보존·대안 연결·실측 한계 지침, v3에서 질문 전체 검색 상위를 주제 풀에 넣고, v4에서 질문에 지역이 없으면 한 지역 데이터는 최대 2점·대표 가중 ×0.6.

| 상위 5개 | 핵심(2점) | 무관(0점) |
|---|---|---|
| 포털 추천 | 55% | 10% |
| 기존 전략 | 40% | 19% |
| **멀티헤드 (v4)** | **72%** | **2%** |

| | 채팅 답이 인용한 데이터 핵심 비율 | 무관 |
|---|---|---|
| 기존 | 45% | 8% |
| 멀티헤드 | 54% | 5% |

**답 판정**: 포털 대비 45:0 · 기존 우리 답 대비 33:12. 판정된 핵심 데이터 중 멀티헤드 상위 10이 덮는 비율 66% (단서 재순위 시제품 54%).
기준별(포털 대비): 관련성 4.76 · 측면 포괄 4.38 (기존 3.98) · 바로 실행 4.58 · 정직성 4.51.

**정답표 32문항(`eval-plan --heads`)**: 전략 재현율 0.92 (규칙 0.94) · 1순위 적중 0.78 (규칙 0.91) · 질문당 12초.
정답표는 기존 규칙 검색으로 사람이 고른 묶음이라 그 방식에 유리하다. 놓친 것은 성수동 일반음식점 인허가, 산업단지 용지, 대중교통 접근성 지표처럼 주제 재순위가 다른 데이터를 더 높게 본 경우다.

**기존 답에 진 12문항의 공통점**(v1 분석) — 주제로 나누면서 같은 주제 안의 검증 조인(bildSn·brandMnno·facilNo)을 놓침 → v2에서 핵심과 선언된 조인으로 이어지는 검증 후보를 조인으로 넣도록 고쳤다.
남은 약점: 같은 대상의 여러 업종·연도판(식품 처분 판매업 등)을 다 보여 주지 못함, 주제당 상위 8개 한도.
