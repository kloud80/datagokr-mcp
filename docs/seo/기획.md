# 검색·AI 노출(SEO·GEO) 기획 — 공개 전략 페이지 `/data`

작성 2026-11-04. 1차 실행분은 맨 아래 "1차 범위"에 적었다.

## 1. 목표

- 검색엔진(구글·네이버·빙)과 AI(ChatGPT 검색·Perplexity·Claude·Gemini 등 웹을 읽는 LLM)가 **"공공데이터로 ○○ 하려면?"** 류의 질문에
  이 사이트의 페이지를 근거로 가져가게 한다.
- 들어온 사람을 **메인 질의 화면(`/?q=…`)으로 다시 보내** 자기 질문으로 전략을 받게 한다 — 페이지는 입구, 서비스는 채팅·MCP.

## 2. 왜 지금 구조로는 안 잡히나

| 문제 | 원인 | 해법 |
|---|---|---|
| 본문이 색인되지 않는다 | 화면이 SPA(`#/docs`, `#/wiki`) — 해시 주소는 한 페이지로 취급되고 본문은 JS로 그린다 | 서버가 완성된 HTML을 주는 별도 경로 `/data/…` |
| 들어올 문이 하나뿐 | 첫 화면 한 장 | 질문·데이터·분야마다 주소가 다른 페이지 수천 장 (롱테일) |
| AI가 인용할 문장이 없다 | 답은 채팅 안에서만 생긴다 | 미리 만든 답을 자연어 문단 + 구조화(JSON-LD)로 공개 |

## 3. 페이지 종류 (롱테일 콘텐츠 축)

| 종류 | 주소 | 재료 | 노리는 검색 | 1차 |
|---|---|---|---|---|
| **전략 사례** | `/data/s/{id}` | 포털 AI 비교 1천 문항 중 우리가 이긴 답(판정 점수 16/20 이상·핵심 데이터 수가 포털 이상) + 새 롱테일 질문 | "○○ 데이터 어디서 받나", "○○랑 ○○ 같이 보려면", "○○ 오픈API 있나" | ✅ |
| **데이터 사전** | `/data/d/{id}` | 검증 데이터 — 실측 필드·빈 값 비율·표본값·호출 주소·행 수·조인 | "국토교통부 ○○ API 필드", "○○ 파일 컬럼", 데이터 이름 그대로 | ✅ (전략에 나온 것 + 공공행정 전부) |
| **분야 허브** | `/data/t/{분야}` | 분야별 전략·데이터 목록 | "공공행정 공공데이터", 내부 링크 허브 | ✅ |
| **허브(목차)** | `/data/` | 전체 안내·최근·분야 | 브랜드·탐색 | ✅ |
| 조인 레시피 | `/data/j/{a}-{b}` | 선언·실측된 조인(매칭률) | "○○ ○○ 조인", "PNU로 잇기" | 2차 |
| 코드표 | `/data/c/{id}` | 코드표 120 (법정동·지목·용도지역 …) | "지목 코드표", "법정동코드 조회" — 검색량 큼 | 2차 |
| 기관별 | `/data/a/{기관}` | 기관별 검증 데이터·전략 | "행정안전부 공공데이터 목록" | 2차 |

전략 사례가 "질문형 롱테일", 데이터 사전이 "고유명사형 롱테일", 코드표·조인이 "실무형 롱테일"이다.
데이터 사전은 실측 통계(필드별 빈 값 비율·유니크·표본)라 포털 메타와 겹치지 않는 고유 본문이다 — 자동 생성 페이지가 얇은 페이지(thin content)로 보이지 않게 하는 핵심.

## 4. 롱테일 질문을 어디서 계속 만드나

1. **포털 AI 비교 1천 문항** — 이미 답·판정이 있다. 이긴 854문항을 1차로 공개.
2. **사용자 실제 질문**(채팅 151 · MCP 472, `logs/usage`) — 원문을 공개하지 않는다(개인 맥락이 섞일 수 있음). 주제만 뽑아 일반화한 질문으로 다시 써서 돌린다.
3. **데이터에서 거꾸로 만든 질문** — 검증 데이터·조인 Edge에서 "이 데이터로 답할 수 있는 질문"을 만든다. 1차는 공공행정(지방행정·재정, 국가통계, 법제, 정부조달, 공정거래, 국민권익, 인사·조직) 롱테일 120문항.
4. **검색어 데이터**(2차) — 서치 콘솔·네이버 서치어드바이저의 노출 검색어 중 페이지가 없는 것 → 질문으로 만들어 페이지 추가. 이것이 계속 굴러가는 바퀴.
5. **채팅에서 좋은 답이 나온 질문**(2차) — 👍 피드백·긴 세션이 나온 질문을 일반화해 페이지 후보로.

## 5. 한 페이지의 구성 (사람과 AI가 같이 읽는 모양)

1. `<h1>` = 질문 그대로 (검색어와 같은 말)
2. **한 문단 답** — 첫 문단만 읽어도 답이 되게 (AI 요약·스니펫용)
3. 전략 본문 — 대표 데이터·고른 이유·잇는 키·주의점 (채팅 답을 HTML로)
4. 데이터 표 — 이름·기관·유형·역할 → 데이터 사전 페이지 링크
5. **포털 AI 검색과 비교** — 핵심 데이터 수·점수·포털이 놓친 점 (판정 근거 그대로, LLM 판정이라는 단서 포함)
6. **"이 질문으로 지금 전략 받기"** → `/?q=질문&ref=seo` (메인에서 자동 실행)
7. **비슷한 질문으로 물어보기** — 아직 페이지가 없는 변형 질문 3개 → `/?q=…` (롱테일 수요를 채팅으로 흡수)
8. 관련 전략·같은 데이터를 쓰는 전략 (내부 링크)
9. JSON-LD: `QAPage`(질문·답) · `BreadcrumbList` / 데이터 사전은 `Dataset`(구글 데이터셋 검색 대상)

## 6. 기술 요건

- 서버 렌더링 HTML(자바스크립트 없이 본문 완결), 페이지마다 `title`·`description`·`canonical`·Open Graph.
- `sitemap.xml`(사이트맵 색인 → 종류별 사이트맵), `robots.txt`에 사이트맵 주소, `llms.txt`에 `/data` 안내.
- IndexNow(빙·네이버·얀덱스가 받는다) — 새 페이지를 바로 알린다. 구글은 서치 콘솔에 사이트맵 제출.
- 검색엔진 소유 확인 메타(구글·네이버)는 환경변수로 넣는다(`PDS_GOOGLE_SITE_VERIFICATION`, `PDS_NAVER_SITE_VERIFICATION`).
- 메인 화면 하단에 작은 링크 "공공데이터 전략 사례" → `/data/`.
  **완전히 숨긴 링크(안 보이게 한 텍스트)는 구글 스팸 정책 위반**이라 작게라도 보이게 둔다.
- 유입 측정: `ref=seo`로 들어온 채팅을 사용 기록에 남겨 `/admin/usage`에서 본다.

## 7. 지표

| 단계 | 지표 | 어디서 |
|---|---|---|
| 색인 | 색인된 페이지 수 | 서치 콘솔 · 서치어드바이저 |
| 노출 | 노출수·검색어 수·평균 순위 | 같음 |
| 유입 | `/data` 방문, AI 크롤러 방문(GPTBot·ClaudeBot·PerplexityBot …) | 서버 접속 기록 |
| 전환 | `ref=seo` 채팅 수, 전환 후 MCP 연결 | `/admin/usage` |

## 8. 단계

| 단계 | 내용 |
|---|---|
| **1차 (지금)** | 전략 사례 854 + 공공행정 롱테일 120, 데이터 사전(전략에 나온 것 + 공공행정), 분야 허브, 사이트맵·robots·llms.txt·IndexNow, 메인 `?q=` 자동 실행·하단 링크 |
| 2차 | 코드표·조인 레시피·기관 페이지, 사용자 질문 일반화 배치, 페이지 본문을 최신 지식으로 다시 생성(지식 버전이 바뀌면) |
| 3차 | 서치 콘솔 검색어 → 질문 → 페이지 자동 순환, 분야별 롱테일 확대(국토·교통·보건 …), 성과 낮은 페이지 정리(noindex) |

## 9. 위험과 원칙

- **사실만** — 페이지의 데이터·수치는 실측·검증 기록에서만. 답 본문은 채팅 답 원문(생성 시점 표기).
- 포털 비교는 판정 근거(LLM 판정)를 밝히고 깎아내리는 표현을 쓰지 않는다.
- 사용자 질문 원문·해시는 공개하지 않는다.
- 페이지 품질 기준 미달(판정 점수 16 미만, 데이터 0개)은 만들지 않는다.
